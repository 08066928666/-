# 产品方案：市面输入法 + 加装实时翻译

## 定位

**不自己做输入法**，在成熟产品上**只加一层「实时翻译」**：

```
┌─────────────────────────────────────┐
│  实时翻译层（我们只做这一块）          │  ← 发：边打边译 / 发送双语
│  收：剪贴板或复制 → 中文对照           │
├─────────────────────────────────────┤
│  市面输入法（已有，不改动核心）        │  ← 仓 / 语燕 / 搜狗等
│  拼音 · 联想 · 词库 · 键盘 UI         │
└─────────────────────────────────────┘
```

开发量可从「做一个输入法」降到「做一个插件 / 小模块」，效率会高很多。

---

## 推荐「底座」输入法

| 平台 | 底座 | 获取方式 | 为何选它 |
|------|------|----------|----------|
| **iPhone** | [仓输入法](https://apps.apple.com/app/id6446617683) | App Store 免费 | Rime、流畅、可 fork 加功能 |
| **Android** | [语燕输入法](https://github.com/gurecn/YuyanIme/releases) | APK / 应用商店 | Rime、开源、可改 APK |
| **不想写代码先用** | 仓 + 系统「翻译」App | 现成安装 | 见 [IPHONE_无需开发.md](IPHONE_无需开发.md) |

搜狗、百度等商用输入法**闭源**，一般无法合法「加装」；开源底座才适合二次开发。

---

## 「实时翻译」要做什么（功能清单）

### 发消息（核心）

| 能力 | 说明 | 用户感受 |
|------|------|----------|
| **输入预览** | 打中文时，键盘上方显示对应英文/日文 | 边打边看，不用切 App |
| **发送翻译** | 点发送/回车时，自动插入「外文 +（中文）」 | 一步发出双语 |
| **目标语切换** | 英 / 日 / 韩 一键切换 | 应对不同聊天对象 |

### 收消息

| 能力 | 说明 | 限制 |
|------|------|------|
| **复制即译** | 复制外文 → 弹出或插入中文对照 | Android 较易实现 |
| **剪贴板监听** | 复制后自动提示译文 | iOS 键盘扩展权限严，常需配合宿主 App |

### 翻译引擎（可替换）

- 演示：内置小词典（本仓库 `Translator` / `SmartTranslate`）
- 正式：DeepL、Google Cloud、OpenAI 等 API（需联网；iOS 键盘扩展要开「完全访问」）

## 加装方式（按开发量从少到多）

### 阶段 0：零开发（你现在就能用）

- 底座：**仓输入法**打字  
- 翻译：系统 **翻译** App，复制粘贴  
- 文档：[IPHONE_无需开发.md](IPHONE_无需开发.md)

### 阶段 1：最小加装（推荐外包范围）

只改 **发送 + 预览**，不动拼音引擎。

| 平台 | 做法 | 本仓库参考 |
|------|------|------------|
| Android | 在语燕 `ImeService` / 发送键上挂 `SmartTranslate` | `ai-ime-yuyan/addon/` |
| iOS | Fork 仓输入法，在回车/发送键调用 `Translator.bilingualSend` | `ai-ime-ios/Shared/Translator.swift` |

预计工作量：**小模块**，不是重做输入法。

### 阶段 2：体验增强

- 剪贴板外文 → 中文对照条  
- 常用句、目标语记忆  
- 宿主 App 做设置页（API Key、是否附带中文）

### 阶段 3：上架

- Apple / 应用商店审核、隐私说明、键盘「完全访问」说明

## 平台限制（设计时要遵守）

### iOS

- 键盘扩展**不能**直接读其他 App 聊天窗口里的字  
- **收消息**：依赖用户**复制**，或单独做一个**小 App** 显示对照  
- **联网翻译**：需在系统里为键盘开启 **允许完全访问**  
- **发消息**：在扩展内拦截「发送/换行」完全可行（仓输入法可改）

### Android

- 输入法权限相对大，剪贴板、发送拦截都更容易  
- 语燕 GPL-3.0：若分发修改版 APK，需遵守开源义务

## 技术架构（给开发者的一页纸）

```
用户打字 ──► 底座输入法(Rime) ──► 中文上屏
                    │
                    ▼
            [翻译层 hook 点]
            · 每次候选变化 → 更新预览条
            · 发送/回车   → translateAndSendLine()
            · 剪贴板变化  → translateIncoming()
                    │
                    ▼
            TranslationService (API)
```

**Hook 原则**：不修改 Rime 分词、候选、词库；只在 `commitText` / `performEditorAction(SEND)` 前后加逻辑。

## 建议落地顺序

1. **你**：仓输入法 + 翻译 App，验证聊天流程是否顺手  
2. **记录**：最烦的是「预览」还是「发送」还是「看懂对方」  
3. **外包/开发**：只做阶段 1（预览 + 发送双语），底座仍用仓/语燕  
4. **接 API**：替换演示词典，做正式翻译质量  

---

## 一句话

**市面输入法负责「好打」，我们只负责「好译」**——这是开发效率最高的路线。

若你准备找开发者，可直接把本文 + `ai-ime-yuyan/addon/` 源码一并给对方作为需求与参考实现。
